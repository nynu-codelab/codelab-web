## 一、上传安全加固

### 修改文件

- `backend/src/main/java/cn/edu/nynu/codelab/upload/service/impl/UploadFileServiceImpl.java`

### 问题

原上传实现仅校验 MIME 类型（客户端声明，可伪造），缺乏对路径穿越和文件头 Magic Bytes 的防御。

### 方案：7 层纵深防御

| 层 | 防御内容 | 说明 |
|---|---|---|
| 1 | 文件非空检查 | 拒绝 `null` 和空文件 |
| 2 | 文件名安全清洗 `sanitizeFilename()` | 拒绝 `../`、`..\\`、空字节截断（`\x00`），仅保留文件名部分 |
| 3 | 扩展名白名单 `extractExtensionSafe()` | 仅允许 `.jpg`、`.jpeg`、`.png`、`.webp`；拒绝双扩展名绕过（`file.tar.gz` → `.gz` 不在白名单）；拒绝无扩展名和隐藏文件 |
| 4 | MIME 类型校验（客户端声明） | `image/jpeg`、`image/png`、`image/webp` |
| 5 | **Magic Bytes 校验（不可伪造）** | JPEG: `FF D8 FF` / PNG: `89 50 4E 47` / WebP: RIFF 头 + `57 45 42 50` |
| 6 | 文件大小上限 | 10MB |
| 7 | 安全存储 | UUID 重命名 + `yyyy/MM/dd` 日期子目录，完整脱离用户输入 |

### 关键实现


## 四、Token 黑名单和登录限流 Redis 化

### 设计目标

原内存实现（`InMemoryTokenBlacklistService`、`InMemoryLoginAttemptService`）在服务重启后丢失，多实例不共享。Redis 化后：

- 任一实例登出，所有实例的 Token 立即失效
- 登录限流跨实例共享计数
- 数据自动过期，无需手动清理

### 新增文件

| 文件 | 说明 |
|---|---|
| `backend/src/main/java/cn/edu/nynu/codelab/config/RedisConfig.java` | 手动创建 `RedisConnectionFactory` 和 `StringRedisTemplate` |
| `backend/src/main/java/cn/edu/nynu/codelab/auth/service/impl/RedisTokenBlacklistService.java` | Redis Token 黑名单实现 |
| `backend/src/main/java/cn/edu/nynu/codelab/auth/service/impl/RedisLoginAttemptService.java` | Redis 登录限流实现 |

### 修改文件

| 文件 | 变更 |
|---|---|
| `backend/pom.xml` | 新增 `spring-boot-starter-data-redis` 和 `commons-pool2` 依赖 |
| `backend/src/main/resources/application.yml` | 排除 `RedisAutoConfiguration`；新增 `app.auth.redis-enabled` 开关和 `app.redis.*` 配置 |
| `backend/src/main/resources/application-docker.yml` | Docker profile 默认启用 Redis（`redis-enabled: true`） |
| `backend/src/main/java/cn/edu/nynu/codelab/auth/service/impl/InMemoryTokenBlacklistService.java` | 新增 `@ConditionalOnProperty` 条件激活 |
| `backend/src/main/java/cn/edu/nynu/codelab/auth/service/impl/InMemoryLoginAttemptService.java` | 新增 `@ConditionalOnProperty` 条件激活 |
| `deploy/docker-compose.yml` | Redis 服务去除 `profiles` 限制（始终启动）；后端注入 Redis 环境变量；Redis 健康检查依赖 |
| `deploy/.env` | 新增 `REDIS_DATABASE=0` |
| `deploy/.env.example` | 新增 `REDIS_DATABASE=0` |

### Redis Key 设计

| 用途 | Key 格式 | Value | TTL |
|---|---|---|---|
| Token 黑名单 | `codelab:auth:blacklist:{sha256(token)}` | `"1"` | token 剩余有效期 |
| 登录尝试计数 | `codelab:auth:login-attempt:{ip}:{username}` | 失败次数 | 10 分钟 |
| 登录锁定标记 | `codelab:auth:login-lock:{ip}:{username}` | `"1"` | 10 分钟 |

> 安全设计：不存储完整 Token，仅保存 SHA-256 摘要，降低 Redis 泄露风险。

### Profile 切换机制

| Profile | `app.auth.redis-enabled` | 实现 |
|---|---|---|
| `local`（默认） | `false` | `InMemoryTokenBlacklistService` + `InMemoryLoginAttemptService` |
| `docker` | `true` | `RedisTokenBlacklistService` + `RedisLoginAttemptService` |

通过 `@ConditionalOnProperty` 自动切换，无需修改任何调用方代码。

### Redis 自动配置排除

Spring Boot 的 `RedisAutoConfiguration` 在 `application.yml` 中被排除：

```yaml
spring:
  autoconfigure:
    exclude:
      - org.springframework.boot.autoconfigure.data.redis.RedisAutoConfiguration
```

改为由 `RedisConfig.java`（仅当 `app.auth.redis-enabled=true` 时激活）手动创建连接工厂。这样在开发环境未启用 Redis 时，应用不会因 Redis 不可达而启动失败。
