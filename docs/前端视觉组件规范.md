# 前端视觉组件规范

## 1. 规范目标

本规范用于沉淀 `refine/pc-immersive-frontend` 分支已经确认的 PC 沉浸式视觉系统，避免后续页面各自发挥。

当前视觉方向继续保持：

```text
工程指挥舱 + 年轻学生技术团队展台
深色高级科技感
动态光网
玻璃拟态卡片
终端 / 代码窗口元素
清爽工程感
CodeLab 实验室感
```

本规范不是重新定义传统学校门户风格，也不是移动端优先规范。本阶段最高优先级仍是 PC 端视觉冲击力、技术实验室氛围和高级动态效果。

## 2. 设计基调

### 2.1 核心关键词

```text
CodeLab
工程实践
终端控制台
构建流水线
节点网络
代码流
年轻学生技术团队
真实项目训练
```

### 2.2 视觉气质

- 页面应像一个对外开放的 CodeLab 工程实验室，而不是普通学院通知站。
- 深色背景负责高级感，青色 / 蓝色 / 绿色光效负责技术感，少量琥珀色用于状态和重点提示。
- 卡片应保持玻璃拟态、轻边框、扫描线、光边缘和可读内容之间的平衡。
- 视觉可以震撼，但业务表单、后台表格、Markdown 正文必须清晰可读。

### 2.3 内容真实性

- 不编造真实成员姓名、真实联系方式、虚假成员数量或虚假项目数量。
- 没有接口支撑的数据只能作为视觉状态、流程说明或明确占位，不写成真实运营成果。
- `/members`、`/contact`、后台成员 / 方向 / 站点配置 / 上传等未接真实接口的模块继续保持占位或能力结构表达。

## 3. 基础视觉系统

### 3.1 色彩

当前主视觉使用以下色彩语义：

| 语义 | 建议色值 | 用途 |
|---|---|---|
| 深空背景 | `#06090f` / `#08111f` | 页面底色、后台控制台底色 |
| 主科技光 | `#53e7ff` | 终端、光边框、主 CTA、节点高亮 |
| 工程绿色 | `#2ff0b6` | 构建通过、在线状态、流程完成 |
| 电蓝 | `#75a7ff` | 次级光效、网络节点、方向卡片 |
| 紫蓝辅助 | `#a98bff` | 层次光晕、特殊模块点缀 |
| 琥珀提示 | `#ffd36a` | 状态提醒、招新重点、注意信息 |

使用要求：

- 不要把页面做成单一蓝紫渐变。
- 琥珀色只用于少量强调，不能变成橙棕主题。
- 正文、表格、表单仍以高对比浅色文字和低透明边框保证阅读效率。

### 3.2 形态

- 卡片圆角控制在 8px 左右，避免过度圆润。
- 首页和大屏区可使用更强透视、光边框、扫描线和动态背景。
- 后台管理端应更克制，优先保证表格、筛选、弹窗、表单清晰。
- 不做卡片套卡片；大段区域用全宽层或网格布局承载。

### 3.3 字体和排版

- 页面标题强调工程感和品牌识别，不使用学校门户式大段套话。
- 终端、代码、命令行区域使用等宽字体。
- 紧凑面板内标题不使用 Hero 级字号。
- 按钮和标签文字必须完整显示，不能因为动效挤压、遮挡或溢出。

## 4. 动效原则

### 4.1 PC 优先

- Canvas 粒子、代码雨、能量流等复杂动效只在 `window.innerWidth >= 1024` 时启用。
- 移动端只保证不白屏、不严重横向崩溃，可以关闭复杂背景动效。
- 不为了移动端细节牺牲 PC 大屏沉浸感。

### 4.2 性能约束

- Canvas 组件卸载时必须 `cancelAnimationFrame`、移除 `resize` 等事件监听。
- DPR 需要设置上限，避免高分屏过重渲染。
- 避免无限创建 DOM、重复注册时间线或页面切换后残留动画。
- 遵守 `prefers-reduced-motion`，减少动画偏好开启时关闭主要入场和 Canvas 动效。

### 4.3 动效语义

- 粒子网络用于空间层次和实验室网络感。
- 代码雨用于 CodeLab 氛围，透明度要低，不能抢正文。
- 能量流用于建立页面节奏和 CTA 导向。
- 扫描线用于项目卡片、控制台和状态面板，不应覆盖主要文字。
- Hover 反馈应强化“可操作”，不要只是随机发光。

## 5. 核心组件使用规范

### 5.1 ParticleUniverse

定位：全局 PC 粒子 / 节点网络背景。

使用位置：

- `AppAnimatedBackground`
- `/design-preview` 背景层
- PC 首页首屏沉浸式背景

使用要求：

- 默认作为背景层存在，不单独放进业务卡片。
- 只在 PC 端启用，移动端关闭。
- 粒子数量和连线距离需要控制，保证首屏和滚动性能。

### 5.2 CodeRainCanvas

定位：低透明代码流背景。

使用位置：

- 首页、文章、项目、认证页等需要强化代码实验室氛围的区域。

使用要求：

- 透明度要低，不能影响标题、表单和 Markdown 阅读。
- 不在后台表格区域上方直接覆盖。
- 内容使用通用命令、技术栈或流程词，不伪造真实日志。

### 5.3 EnergyFlowBackground

定位：能量流、光束、光环背景层。

使用位置：

- 首页 Hero
- 招新 CTA
- 重要过渡区

使用要求：

- 用于建立空间纵深和动线，不用于堆满每个页面。
- 与 `ParticleUniverse` 叠加时控制透明度，避免页面发灰或视觉噪声过高。

### 5.4 TerminalHero

定位：首页主视觉核心组件。

使用位置：

- 只建议放在 `/` 首页 Hero。

推荐信息结构：

```text
左侧：品牌标题 + 简短价值表达 + CTA
右侧：终端 / 代码窗口 / Lab 状态面板
背景：粒子网络 + 能量流 + 动态网格 + 光晕
```

使用要求：

- 主标题必须清晰，不被光效、窗口或扫描线遮挡。
- 终端命令表达真实训练方向，例如 `boot --lab nynu-codelab`、`build --stack java vue mysql docker`。
- 不写虚假的成员数、项目数和上线成果。

### 5.5 CommandConsole

定位：页面级命令控制台。

使用位置：

- `/about`：实验室运行方式
- `/directions`：技术方向矩阵
- `/projects` / `/projects/:id`：项目构建状态、仓库和演示信息
- `/articles` / `/articles/:id`：知识库检索、Markdown 文档感
- `/recruit`：报名流程命令
- `/login` / `/register`：Access Console
- `/profile` / `/my-application`：个人状态与报名状态

使用要求：

- 命令内容必须和页面主题相关。
- 嵌入已有大卡片内部时使用轻量形态，避免卡片套卡片。
- 不把命令行当作装饰堆满页面，每页 1 到 2 个关键控制台即可。

### 5.6 LabControlPanel

定位：实验室状态面板。

使用位置：

- 首页 Hero 右侧或 Hero 后第一屏。
- 招新页状态说明。
- 后续真实站点配置接入后可展示公开状态。

使用要求：

- 当前可展示 `RECRUITING`、`PROJECT PRACTICE`、`LEARN BY BUILDING` 等状态语义。
- 不展示无法证明的统计数字。
- 状态灯颜色要有语义：在线 / 招新中 / 构建通过 / 待接入。

### 5.7 BuildPipeline

定位：构建流水线和流程节点。

使用位置：

- 首页：`Design -> Code -> Review -> Deploy`
- `/recruit`：`register() -> login() -> submitApplication() -> adminReview() -> joinCodeLab()`
- `/projects/:id`：项目从需求到部署的流程表达
- 后台：模块接入状态或审核流程提示

使用要求：

- 只表达真实业务流程或学习流程。
- 节点数量不要过多，PC 端以 4 到 6 个节点为宜。
- 流程线可以有能量动效，但不能影响表单操作。

### 5.8 GitBranchMap

定位：团队协作和学习路径的分支图。

使用位置：

- `/about`：实验室工作方式
- `/members`：能力结构和协作方式
- `/directions`：方向之间的连接

使用要求：

- 表达“分支、合并、评审、发布”的工程协作语言。
- 不用于展示真实 Git commit，除非后续接入真实数据。

### 5.9 DataCounter

定位：数字指标动效。

使用位置：

- 首页工程状态指标。
- 后台 Dashboard 真实统计项。

使用要求：

- 只能用于真实数据或明确的流程节点数量。
- 不编造 `100+ 成员`、`300+ 项目` 一类无法证明的运营数据。
- 无真实数据时可使用非数字状态标签替代。

### 5.10 ProjectCard / ArticleCard / DirectionCard

定位：主要内容卡片。

使用位置：

- `/projects`
- `/articles`
- `/directions`
- 首页精选区

使用要求：

- 项目卡片可使用扫描线、`BUILD PASS`、技术栈光标标签，但不能伪造接口字段。
- 文章卡片可使用知识库、文档、代码块纹理，但 Markdown 安全策略不变。
- 方向卡片可使用节点环绕、技术栈芯片和 3D hover，但保持文案可读。

## 6. 页面使用矩阵

| 页面 | 推荐组件 | 重点 |
|---|---|---|
| `/` | `TerminalHero`、`LabControlPanel`、`BuildPipeline`、`DataCounter` | PC 大屏沉浸式入口 |
| `/about` | `CommandConsole`、`GitBranchMap`、流程卡片 | 实验室文化和运行方式 |
| `/directions` | `CommandConsole`、方向卡片、技术栈芯片 | 技术方向矩阵 |
| `/members` | `GitBranchMap`、能力结构卡片 | 不编造成员名单 |
| `/projects` | `CommandConsole`、项目扫描卡片 | 项目展台 |
| `/projects/:id` | `CommandConsole`、代码窗口、Markdown 样式 | 项目详情和文档质感 |
| `/articles` | `CommandConsole`、知识库卡片 | CodeLab Knowledge Base |
| `/articles/:id` | Markdown 样式、代码块视觉 | 安全阅读和工程文档感 |
| `/recruit` | `BuildPipeline`、命令式流程、强 CTA | 加入 CodeLab 的工程训练营 |
| `/login`、`/register` | `AuthShell`、Access Console | 表单清晰优先 |
| `/profile`、`/my-application` | 状态面板、命令控制台 | 登录后个人状态 |
| `/contact` | 状态卡片、占位说明 | 不展示虚假联系方式 |

| `/admin/*` | 状态灯、控制台标题、ECharts 概览 | 管理效率优先 |

## 7. 后台视觉规范

后台方向是 `Admin Console`，不是比前台更花的展示页。

要求：

- Element Plus 仍是唯一后台 UI 组件库。
- 表格、筛选、弹窗、表单清晰优先。
- 可以使用状态灯、模块卡片、控制台标题、轻量扫描线和 ECharts 概览。
- 后台空状态可以有科技感，但不要影响管理员判断。
- `admin-web npm run build` 当前因 ECharts Dashboard chunk 有体积提醒，构建通过；后续如继续扩展图表，应优先考虑动态拆包。

## 8. Logo 使用方向

Logo 应比页面动效更克制，优先满足：

- 简洁
- 可缩小
- 可作为 favicon
- 能和深色科技界面共存
- 具备 CodeLab / 终端 / 代码识别

当前建议保留 3 类候选方向：

| 方向 | 说明 | 适合场景 |
|---|---|---|
| CL 终端提示符 | 用 `CL`、终端光标和提示符形成紧凑标识 | 页眉、favicon、后台登录 |
| 代码括号符号 | 用 `< / >` 与 `CL` 融合 | 文档封面、官网品牌露出 |
| CL 方形小标 | 用深色方形底和极简 `CL` 线条形成应用图标 | favicon、PWA、后台图标 |

当前已确认“终端提示符 + C 形框 + 光标竖线 + 琥珀状态点”方向，并已落地为站内 SVG mark 与 favicon。Logo 使用现有官网 token：`#06090f`、`#0b1220`、`#53e7ff`、`#2ff0b6`、少量 `#ffd36a`。

已接入位置：

- 前台页眉 `AppHeader`
- 前台页脚 `AppFooter`
- 前台 favicon
- 后台侧栏 `AdminLayout`
- 后台登录 `LoginView`
- 后台 favicon

Logo 动效应保持克制：允许状态点轻微呼吸、hover 扫光和低强度光边，不应添加复杂粒子、重 3D 或额外 Canvas。

## 9. 后续扩展检查清单

新增页面或继续增强视觉时，先检查：

1. 是否保持“工程指挥舱 + 年轻学生技术团队展台”方向。
2. 是否优先复用已有组件，而不是新造一套视觉语言。
3. 是否没有编造真实数据。
4. 是否没有影响登录、报名、文章、项目等业务闭环。
5. 是否保持 Markdown `html:false` 或等价防护。
6. 是否在移动端关闭或降级复杂 Canvas 动效。
7. 是否在组件卸载时释放 Canvas / 动画资源。
8. 是否更新 README.md、AGENTS.md 和需求文档中的相关状态。
