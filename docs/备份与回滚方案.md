> 日期：2026-06-22

>

## 一、备份体系总览

| 备份对象 | 备份方式 | 周期建议 | 保留策略 |
|----------|---------|----------|----------|
| MySQL 数据库 | `mysqldump` SQL 导出 | 每日 | 至少保留最近 7 天 |
| 上传文件目录 | `tar -czf` 归档压缩 | 每日 | 至少保留最近 7 天 |
| Redis 数据 | AOF 持久化（自动） | 实时 | 非核心业务主数据，AOF 即可 |

## 二、MySQL 数据库备份与恢复

### 2.1 备份前提

- Docker Compose 服务正常运行
- `deploy/.env` 中已配置 `MYSQL_USERNAME` 和 `MYSQL_PASSWORD`
- 备份目录已创建：`mkdir -p /opt/codelab/backup/mysql`

### 2.2 备份命令

```bash
# 从 deploy/.env 读取数据库连接信息
source deploy/.env

# 执行全量备份
docker compose --env-file deploy/.env -f deploy/docker-compose.yml exec -T mysql \
  mysqldump \
    -u"$MYSQL_USER" \
    -p"$MYSQL_PASSWORD" \
    --single-transaction \
    --routines \
    --triggers \
    --events \
    --set-gtid-purged=OFF \
    "$MYSQL_DATABASE" \
  > /opt/codelab/backup/mysql/codelab_$(date +%Y%m%d_%H%M%S).sql

# 压缩备份文件（节省空间）
gzip /opt/codelab/backup/mysql/codelab_*.sql
```

### 2.3 恢复命令

```bash
# 从 deploy/.env 读取数据库连接信息
source deploy/.env

# 指定要恢复的备份文件
BACKUP_FILE="/opt/codelab/backup/mysql/codelab_20260622_030000.sql"

# 如果是 gzip 压缩的备份，先解压
# gunzip "${BACKUP_FILE}.gz"

# ⚠️ 恢复前必须停止写入操作
# 可通过关闭招新开关或暂时停止后端容器来阻止用户写入
# docker compose --env-file deploy/.env -f deploy/docker-compose.yml stop backend

# 执行恢复
docker compose --env-file deploy/.env -f deploy/docker-compose.yml exec -T mysql \
  mysql \
    -u"$MYSQL_USER" \
    -p"$MYSQL_PASSWORD" \
    "$MYSQL_DATABASE" \
  < "$BACKUP_FILE"

# 恢复完成后启动后端（如果之前停止了）
# docker compose --env-file deploy/.env -f deploy/docker-compose.yml start backend
```

### 2.4 恢复注意事项

1. **恢复前必须停止写入**：否则可能出现数据不一致。可临时停止 backend 容器或在后台关闭招新开关
2. **恢复前先备份当前数据库**：即使当前数据有问题，也要保留一份恢复前的快照以备回溯
3. **验证恢复结果**：恢复后检查关键表（`sys_user`、`lab_apply_record` 等）的行数和数据完整性
4. **备份文件离线保存**：除服务器本地备份外，定期将备份文件传输到其他存储（如 NAS、云存储）
5. **恢复后同步清理 Token 黑名单**：恢复的数据库可能包含已失效的 Token 记录，建议恢复后手动清理 Redis 相关 Key

### 2.5 备份脚本模板

```bash
#!/usr/bin/env bash
# ============================================================
# MySQL 数据库备份脚本
# 用法：./backup-mysql.sh
# 建议通过 crontab 每日凌晨执行
# ============================================================
set -euo pipefail

PROJECT_DIR="/opt/codelab/app/nynu-code-lab"
BACKUP_DIR="/opt/codelab/backup/mysql"
RETENTION_DAYS=7

cd "$PROJECT_DIR"
source deploy/.env

mkdir -p "$BACKUP_DIR"

BACKUP_FILE="$BACKUP_DIR/codelab_$(date +%Y%m%d_%H%M%S).sql"

docker compose --env-file deploy/.env -f deploy/docker-compose.yml exec -T mysql \
  mysqldump \
    -u"$MYSQL_USER" \
    -p"$MYSQL_PASSWORD" \
    --single-transaction \
    --routines \
    --triggers \
    "$MYSQL_DATABASE" \
  > "$BACKUP_FILE"

gzip "$BACKUP_FILE"

echo "备份完成：${BACKUP_FILE}.gz"

# 清理超过保留天数的旧备份
find "$BACKUP_DIR" -name "codelab_*.sql.gz" -mtime +$RETENTION_DAYS -delete
echo "已清理 ${RETENTION_DAYS} 天前的旧备份"
```

### 2.6 Crontab 定时备份

```bash
# 编辑 crontab
crontab -e

# 添加以下行（每日凌晨 3:00 执行）
0 3 * * * /opt/codelab/app/nynu-code-lab/scripts/backup-mysql.sh >> /opt/codelab/logs/backup-mysql.log 2>&1
```

## 三、上传目录备份与恢复

### 3.1 备份前提

上传文件是业务核心数据，**不能仅依赖容器内部存储**。当前 `docker-compose.yml` 已配置 `uploads-data` named volume，文件持久化在 Docker 管理的卷中。

### 3.2 备份命令

```bash
# 创建备份目录
mkdir -p /opt/codelab/backup/uploads

# 方式一：通过临时容器访问 volume 备份
docker run --rm \
  -v nynu-code-lab_uploads-data:/data:ro \
  -v /opt/codelab/backup/uploads:/backup \
  alpine \
  tar -czf /backup/uploads_$(date +%Y%m%d_%H%M%S).tar.gz -C /data .

# 方式二：如果 volume 绑定到宿主机路径（推荐生产配置），直接 tar
# tar -czf /opt/codelab/backup/uploads/uploads_$(date +%Y%m%d_%H%M%S).tar.gz -C /opt/codelab/data uploads
```

### 3.3 恢复命令

```bash
# 指定要恢复的备份文件
BACKUP_FILE="/opt/codelab/backup/uploads/uploads_20260622_030000.tar.gz"

# 方式一：通过临时容器恢复到 volume
docker run --rm \
  -v nynu-code-lab_uploads-data:/data \
  -v /opt/codelab/backup/uploads:/backup:ro \
  alpine \
  tar -xzf "/backup/$(basename "$BACKUP_FILE")" -C /data

# 方式二：如果 volume 绑定到宿主机路径
# tar -xzf "$BACKUP_FILE" -C /opt/codelab/data
```

### 3.4 上传目录备份注意事项

1. **数据库和上传文件必须配对恢复**：数据库 `lab_upload_file` 表中存储了文件 URL，如果只恢复数据库不恢复对应上传文件，会导致 URL 指向不存在的文件
2. **恢复上传文件前备份当前状态**：即使当前数据有问题也先备份
3. **上传目录不要放在 Web 根目录下**：当前通过 Docker named volume + Nginx `alias` 精确路径暴露，安全性符合要求
4. **上传目录权限**：确保恢复后目录权限正确（容器内应用可读写，Nginx 只读）

### 3.5 上传目录备份脚本模板

```bash
#!/usr/bin/env bash
# ============================================================
# 上传文件备份脚本
# 用法：./backup-uploads.sh
# ============================================================
set -euo pipefail

BACKUP_DIR="/opt/codelab/backup/uploads"
RETENTION_DAYS=7
VOLUME_NAME="nynu-code-lab_uploads-data"

mkdir -p "$BACKUP_DIR"

BACKUP_FILE="$BACKUP_DIR/uploads_$(date +%Y%m%d_%H%M%S).tar.gz"

docker run --rm \
  -v "${VOLUME_NAME}:/data:ro" \
  -v "$BACKUP_DIR:/backup" \
  alpine \
  tar -czf "/backup/$(basename "$BACKUP_FILE")" -C /data .

echo "备份完成：$BACKUP_FILE"

# 清理旧备份
find "$BACKUP_DIR" -name "uploads_*.tar.gz" -mtime +$RETENTION_DAYS -delete
echo "已清理 ${RETENTION_DAYS} 天前的旧备份"
```

## 四、Redis 数据说明

### 4.1 Redis 在当前项目中的作用

| 用途 | Key 格式 | 数据性质 |
|------|----------|----------|
| Token 黑名单 | `codelab:auth:blacklist:{sha256(token)}` | 安全数据，有 TTL 自动过期 |
| 登录尝试计数 | `codelab:auth:login-attempt:{ip}:{username}` | 限流数据，有 TTL 自动过期 |
| 登录锁定标记 | `codelab:auth:login-lock:{ip}:{username}` | 限流数据，有 TTL 自动过期 |

### 4.2 Redis 数据持久化策略

当前 `docker-compose.yml` 中 Redis 使用 AOF（Append Only File）持久化：

```yaml
redis:
  command: redis-server --appendonly yes ${REDIS_PASSWORD:+--requirepass ${REDIS_PASSWORD}}
  volumes:
    - redis-data:/data
```

### 4.3 Redis 数据丢失影响评估

| 场景 | 影响 | 严重程度 |
|------|------|----------|
| Redis 重启（AOF 正常） | 无影响，数据自动恢复 | 无 |
| Redis AOF 文件丢失 | 已登出 Token 黑名单丢失，旧 Token 可被重新使用 | **安全降级**，非致命 |
| Redis 完全不可用 | 后端启动失败（`depends_on` redis healthy） | **服务中断**，需修复 Redis |

### 4.4 Redis 安全建议

1. **生产环境必须设置 Redis 密码**：在 `deploy/.env` 中 `REDIS_PASSWORD` 设置强密码
2. **Redis 端口不公网暴露**：当前 `REDIS_PORT` 仅映射到宿主机 `127.0.0.1` 或内网
3. **Redis 只允许 Docker 内网或本机访问**：通过防火墙限制
4. **Token 黑名单不存储完整 Token**：当前使用 SHA-256 摘要，即使 Redis 泄露也仅暴露摘要值

### 4.5 不单独备份 Redis 的理由

Redis 中的数据均有 TTL 自动过期，且不是核心业务主数据：
- Token 黑名单会在 Token 自然过期后自动清理
- 登录限流计数在 10 分钟后自动过期
- 丢失后的影响是安全降级而非数据丢失
- AOF 持久化已提供重启恢复能力

如果 Redis 数据丢失，最坏情况是已登出的 Token 在剩余有效期内仍然可用，属于安全降级而非数据丢失。业务主数据（用户、报名、文章、项目等）均在 MySQL 中。

## 五、首次部署回滚方案

### 5.1 回滚原则

1. 部署前必须记录当前 commit hash
2. 部署前必须备份 MySQL 和 uploads
3. 回滚时优先停止新容器，恢复旧版本代码
4. 如数据库结构已变更，需恢复数据库备份
5. 如上传目录已变更，需恢复 uploads 备份

### 5.2 部署前准备

```bash
# 1. 记录当前 commit hash
cd /opt/codelab/app/nynu-code-lab
git rev-parse HEAD > /tmp/pre-deploy-commit.txt
echo "部署前 commit: $(cat /tmp/pre-deploy-commit.txt)"

# 2. 备份 MySQL（使用第二节的备份命令）
source deploy/.env
mkdir -p /opt/codelab/backup/mysql
docker compose --env-file deploy/.env -f deploy/docker-compose.yml exec -T mysql \
  mysqldump -u"$MYSQL_USER" -p"$MYSQL_PASSWORD" --single-transaction \
  "$MYSQL_DATABASE" > /opt/codelab/backup/mysql/pre_deploy_$(date +%Y%m%d_%H%M%S).sql

# 3. 备份上传文件
mkdir -p /opt/codelab/backup/uploads
docker run --rm \
  -v nynu-code-lab_uploads-data:/data:ro \
  -v /opt/codelab/backup/uploads:/backup \
  alpine tar -czf /backup/pre_deploy_uploads_$(date +%Y%m%d_%H%M%S).tar.gz -C /data .
```

### 5.3 回滚步骤

# 2. 恢复到上一个稳定 commit

git checkout "$PREVIOUS_COMMIT"

# 3. 如果数据库结构已变更，恢复数据库备份

#   < /opt/codelab/backup/mysql/pre_deploy_*.sql

# 4. 如果上传目录已变更，恢复 uploads 备份

```bash

# 后台管理

# 上传文件访问（替换为实际上传文件 URL）

```

### 5.5 回滚失败应急预案

如回滚过程中出现意外：

1. **Docker 无法启动旧版本**：检查构建日志 `docker compose logs backend`，确认是否有代码依赖问题
2. **数据库恢复后表不存在**：检查 `deploy/mysql/init/01-init.sql` 是否包含所需建表语句，旧版本可能需要手动补建表
3. **Nginx 无法访问**：检查 `nginx.conf` 与当前 docker-compose volume 挂载是否一致
4. **最坏情况**：保留数据卷（`mysql-data`、`redis-data`、`uploads-data`），使用 `docker compose down`（不带 `-v`）停止容器，数据不会丢失，另行排查

## 六、备份策略汇总

### 6.1 推荐备份周期

| 备份项 | 周期 | 命令 | 保留 |
|--------|------|------|------|
| MySQL 数据库 | 每日 03:00 | `backup-mysql.sh` | 7 天 |
| 上传文件 | 每日 03:30 | `backup-uploads.sh` | 7 天 |
| Redis | 不单独备份 | 依赖 AOF | — |
| Nginx 日志 | logrotate 每日 | 系统 logrotate | 30 天 |

### 6.2 定期恢复演练

生产环境上线后，建议每月执行一次恢复演练：

1. 在独立测试环境中恢复最近一次 MySQL 备份
2. 恢复最近一次 uploads 备份
3. 验证数据库和上传文件的一致性（`lab_upload_file` 表中的 URL 与物理文件对应）
4. 启动应用，验证公开接口和后台登录

### 6.3 当前阶段说明

- 本阶段提供命令模板，暂不新增备份脚本文件到 `scripts/` 目录
- 上线前将备份脚本模板中的内容保存为实际脚本并加入 crontab
- 备份脚本必须从 `deploy/.env` 读取环境变量，**禁止硬编码密码**
