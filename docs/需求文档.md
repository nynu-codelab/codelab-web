# 南阳师范学院软件工程实验室官网与招新管理系统需求文档

## 1. 项目基本信息

### 1.1 项目名称

中文名称：

```text
南阳师范学院软件工程实验室官网与招新管理系统
```

英文名称 / Git 仓库名：

```text
nynu-se-lab
```

全称可理解为：

```text
Nanyang Normal University Software Engineering Lab
```

### 1.2 项目定位

本项目是南阳师范学院软件工程实验室自建展示站与招新管理系统，主要用于实验室介绍、技术方向展示、核心成员展示、项目成果展示、学习文章沉淀、在线招新报名和后台内容管理。

本网站不是学校官方门户网站，而是实验室自建的技术展示与招新平台。

建议在网站页脚展示以下声明：

```text
本网站为南阳师范学院软件工程实验室自建展示站，非学校官方门户网站。
```

### 1.3 项目目标

本项目的核心目标包括：

1. 建设实验室对外展示窗口，提升实验室形象。
2. 展示实验室技术方向、核心成员、项目成果和活动动态。
3. 沉淀实验室内部学习文章、技术分享、项目复盘等内容。
4. 支持学生在线注册、登录和提交招新报名。
5. 支持管理员在后台维护官网内容和审核报名信息。
6. 为实验室后续长期运营、成员协作和内容沉淀打基础。

## 2. 技术选型

### 2.1 总体技术栈

本项目采用前后端分离架构。

后端：

```text
Spring Boot
Java 17
MySQL 8
MyBatis-Plus
Sa-Token 或 Spring Security
JWT 登录认证
Knife4j / Swagger 接口文档
Lombok
```

前端：

```text
Vue 3
Vite
TypeScript
Vue Router
Pinia
Axios
Markdown 渲染组件
```

后台管理端：

```text
Vue 3
Vite
TypeScript
Element Plus 或 Arco Design Vue
```

说明：

后台管理端组件库由实现阶段根据开发效率选择，优先考虑 Element Plus 或 Arco Design Vue。选定后全项目必须统一使用一种组件库，不允许混用多个 UI 组件库。

### 2.2 文章方案

学习文章正文使用 Markdown 存储和渲染。

文章内容由后台发布，前台负责展示。后端保存 Markdown 原文，前端通过 Markdown 渲染组件进行展示。

### 2.3 部署方案

项目部署到自己的服务器。

建议部署结构：

```text
Nginx
Spring Boot Jar
MySQL
前台静态资源
后台管理端静态资源
```

后期可扩展：

```text
Docker Compose
Redis
对象存储

日志监控
```

## 4. 核心业务规则

### 4.1 注册规则

注册开放给所有人。

注册字段建议：

```text
用户名
密码
确认密码
姓名
手机号
年级
专业
班级
```

第一版手机号必填，但不接短信验证码。

用户名必须唯一，手机号也建议唯一。

密码必须加密存储，禁止明文存储，禁止使用简单 MD5 存储，建议使用 BCrypt。

### 4.2 登录规则

用户使用用户名和密码登录。

登录成功后返回 Token，前端保存 Token 并在后续请求中携带。

普通用户进入个人中心，管理员进入后台管理端。

### 4.3 报名规则

用户必须登录后才能提交招新报名。

第一版建议一个用户只能存在一条当前报名记录，避免重复提交多份报名表。

报名审核结果只在系统内展示，不做短信、邮件或 QQ 通知。

### 4.4 报名状态

报名状态包括：

```text
待审核
初筛通过
面试中
已通过
未通过
已撤回
```

管理员可以修改报名状态，并填写审核备注。

用户可以在个人中心查看自己的报名状态和审核备注。

## 6. 报名表设计

### 6.1 已确认字段

用户已确认的报名字段：

```text
姓名
年级
专业
班级
手机号
技术方向

```

### 6.2 建议最终字段

建议第一版报名表最终使用以下字段：

```text
姓名
年级
专业
班级
手机号
QQ号
意向技术方向
是否有编程基础
已掌握技术
个人介绍
加入实验室的原因
每周可投入时间
项目 / 作品链接
```

### 6.3 字段说明

| 字段        | 是否必填 | 说明                         |
| --------- | ---- | -------------------------- |
| 姓名        | 是    | 报名人真实姓名                    |
| 年级        | 是    | 例如 2024 级、大一、大二            |
| 专业        | 是    | 学生专业                       |
| 班级        | 是    | 学生所在班级                     |
| 手机号       | 是    | 联系方式，第一版不做短信验证码            |
| QQ号       | 建议必填 | 后续联系使用                     |
| 意向技术方向    | 是    | Java 后端、前端开发、微信小程序等        |
| 是否有编程基础   | 是    | 便于初筛                       |
| 已掌握技术     | 否    | 例如 Java、HTML、CSS、Vue、MySQL |
| 个人介绍      | 是    | 简要介绍个人情况                   |
| 加入实验室的原因  | 建议必填 | 判断动机                       |
| 每周可投入时间   | 建议必填 | 判断时间投入                     |
| 项目 / 作品链接 | 否    | GitHub、Gitee、博客或作品地址       |

## 12. 安全与质量要求

### 12.1 账号安全

```text
密码必须加密存储
禁止明文存储密码
禁止使用简单 MD5 存储密码
登录接口需要基础限流
支持用户禁用
Token 需要设置有效期
```

### 12.2 权限控制

```text
游客只能访问公开接口
普通用户只能访问自己的报名信息
管理员才能访问后台管理接口
后台接口必须统一鉴权
```

### 12.3 数据校验

```text
注册字段必须校验
手机号格式必须校验
报名表字段必须校验
文章标题不能为空
Markdown 内容不能为空
项目名称不能为空
上传文件类型必须限制
```

### 12.4 文件上传安全

```text
限制文件大小
限制文件类型
禁止上传可执行文件
上传文件重新命名
不要直接使用用户原始文件名作为存储文件名
```

### 12.5 前端质量

```text
前台页面需要适配 PC
核心页面需要适配移动端
后台页面以 PC 管理为主
接口请求统一封装
Token 统一处理
错误提示统一处理
```

## 15. 备注

本项目第一版重点是完成可上线、可展示、可招新、可维护的完整闭环。

不要在第一版过度追求复杂权限、站内消息、论坛、评论、通知等扩展功能。应优先保证：

```text
页面完整
流程闭环
数据可靠
后台可维护
部署简单
风格统一
```

后续可以根据实验室实际使用情况继续扩展成员空间、文章评论、内部任务、学习路线、实验室知识库等能力。
