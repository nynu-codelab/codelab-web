# 文件上传与静态资源配置

> 日期：2026-06-22

## 1. 后端上传配置

### 1.1 配置文件

`backend/src/main/resources/application.yml`：

```yaml
spring:
  servlet:
    multipart:
      enabled: true
      max-file-size: 10MB
      max-request-size: 10MB

app:
  upload:
    base-path: ${UPLOAD_BASE_PATH:uploads}
    url-prefix: /uploads
```

### 1.2 配置项说明

| 配置项 | 环境变量 | 默认值 | 说明 |
|--------|----------|--------|------|
| `spring.servlet.multipart.max-file-size` | — | `10MB` | 单文件最大大小 |
| `spring.servlet.multipart.max-request-size` | — | `10MB` | 单次请求最大大小 |
| `app.upload.base-path` | `UPLOAD_BASE_PATH` | `uploads` | 文件存储根目录（相对或绝对路径） |
| `app.upload.url-prefix` | — | `/uploads` | 文件对外访问的 URL 前缀 |

### 1.3 存储路径规则

文件按年月分层存储于 `base-path` 下：

```
{base-path}/
└── 2026/
    └── 06/
        └── a1b2c3d4-e5f6-7890-abcd-ef1234567890.jpg
```

- 本地开发：默认 `uploads` 目录在 backend 项目根目录下（即 `backend/uploads/`）
- Docker 部署：通过环境变量 `UPLOAD_BASE_PATH=/app/uploads`，并使用 volume 挂载到宿主机
- `url-prefix` 为 `/uploads`，前端访问路径为 `/uploads/2026/06/uuid.jpg`

## 2. 支持的文件类型

| 类型 | 扩展名 | MIME 类型 |
|------|--------|-----------|
| JPEG | `.jpg` `.jpeg` | `image/jpeg` |
| PNG | `.png` | `image/png` |
| WebP | `.webp` | `image/webp` |

限制：
- 仅允许以上图片类型，禁止上传可执行文件、脚本、压缩包等
- 单文件最大 10MB
- 类型校验在后端 `UploadFileServiceImpl` 中基于文件扩展名和 MIME 类型双重检查

## 3. 文件命名规则

上传文件重命名为 `UUID + 原始扩展名`，确保文件名唯一，避免覆盖和路径遍历攻击：

```
原始文件名: 团队合照.png
存储文件名: a1b2c3d4-e5f6-7890-abcd-ef1234567890.png
```

数据库 `lab_upload_file` 表同时记录：

| 字段 | 说明 | 示例 |
|------|------|------|
| `original_name` | 原始文件名 | `团队合照.png` |
| `stored_name` | 存储文件名 | `a1b2c3d4-e5f6-7890-abcd-ef1234567890.png` |
| `file_size` | 文件大小（字节） | `2048576` |
| `mime_type` | MIME 类型 | `image/png` |
| `usage_type` | 用途类型 | `cover` / `avatar` / `other` |
| `access_url` | 访问 URL | `/uploads/2026/06/a1b2c3d4-e5f6-7890-abcd-ef1234567890.png` |
| `file_path` | 存储路径 | `uploads/2026/06/a1b2c3d4-e5f6-7890-abcd-ef1234567890.png` |

## 4. 上传接口

### 4.1 接口信息

| 项目 | 说明 |
|------|------|
| 路径 | `POST /api/admin/upload` |
| 权限 | ADMIN |
| Content-Type | `multipart/form-data` |
| 参数 | `file`（文件，必填）、`usageType`（用途类型，可选，默认 `other`） |

### 4.2 请求示例

```bash
curl -X POST http://localhost/api/admin/upload \
  -H "Authorization: Bearer <token>" \
  -F "file=@/path/to/image.jpg" \
  -F "usageType=cover"
```

### 4.3 响应示例

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "id": 1,
    "originalName": "image.jpg",
    "storedName": "a1b2c3d4-e5f6-7890-abcd-ef1234567890.jpg",
    "fileSize": 2048576,
    "mimeType": "image/jpeg",
    "usageType": "cover",
    "accessUrl": "/uploads/2026/06/a1b2c3d4-e5f6-7890-abcd-ef1234567890.jpg",
    "filePath": "uploads/2026/06/a1b2c3d4-e5f6-7890-abcd-ef1234567890.jpg",
    "createTime": "2026-06-22T10:30:00"
  }
}
```

### 4.4 其他管理接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/admin/upload` | 获取最近上传文件列表（最近 50 条） |
| DELETE | `/api/admin/upload/{id}` | 删除文件记录（不删除物理文件） |

## 5. Nginx 配置示例

### 5.1 基础配置

```nginx
# 上传文件静态服务
location /uploads/ {
    alias /usr/share/nginx/html/uploads/;
    expires 30d;
    add_header Cache-Control "public, immutable";
}
```

### 5.2 完整 Nginx 配置片段

```nginx
server {
    listen 80;
    server_name your-domain.com;

    # 上传文件静态服务 —— 必须在 /api/ 反向代理之前
    location /uploads/ {
        alias /usr/share/nginx/html/uploads/;
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    # 后端 API 反向代理
    location /api/ {
        proxy_pass http://backend:8080/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        client_max_body_size 10m;
    }

    # 前台 SPA
    location / {
        root /usr/share/nginx/html/web;
        index index.html;
        try_files $uri $uri/ /index.html;
    }

    # 后台 SPA
    location /admin/ {
        alias /usr/share/nginx/html/admin-web/;
        try_files $uri $uri/ /admin/index.html;
    }
}
```

注意：`location /uploads/` 必须在 `location /api/` 之前或之后皆可（因为路径不冲突），`alias` 末尾的 `/` 不可省略。

## 6. Docker 部署注意

### 6.1 Volume 挂载

Docker Compose 中 uploads 目录必须使用 named volume 或 bind mount 挂载，确保容器重建后文件不丢失：

```yaml
# docker-compose.yml 关键片段
services:
  backend:
    volumes:
      - uploads_data:/app/uploads
    environment:
      - UPLOAD_BASE_PATH=/app/uploads

  nginx:
    volumes:
      - uploads_data:/usr/share/nginx/html/uploads:ro
    # 只读挂载，防止 Nginx 容器修改文件

volumes:
  uploads_data:
```

### 6.2 完整 docker-compose.yml volumes 配置

```yaml
services:
  mysql:
    volumes:
      - mysql_data:/var/lib/mysql
      - ./mysql/init:/docker-entrypoint-initdb.d:ro

  backend:
    volumes:
      - uploads_data:/app/uploads
    environment:
      - UPLOAD_BASE_PATH=/app/uploads

  nginx:
    volumes:
      - ./nginx/nginx.conf:/etc/nginx/conf.d/default.conf:ro
      - ../web/dist:/usr/share/nginx/html/web:ro
      - ../admin-web/dist:/usr/share/nginx/html/admin-web:ro
      - uploads_data:/usr/share/nginx/html/uploads:ro
    ports:
      - "${NGINX_PORT:-80}:80"

volumes:
  mysql_data:
  uploads_data:
```

### 6.3 环境变量

在 `deploy/.env` 中设置：

```bash
UPLOAD_BASE_PATH=/app/uploads
```

### 6.4 .dockerignore

确保 `backend/.dockerignore` 排除本地 uploads 目录：

```
uploads/
target/
.git/
*.log
```

## 7. 生产环境建议

### 7.1 使用独立 Volume

生产环境建议使用 Docker named volume，而非 bind mount：

```yaml
volumes:
  uploads_data:
    driver: local
    driver_opts:
      type: none
      device: /data/nynu-code-lab/uploads
      o: bind
```

或将 uploads 挂载到独立的数据盘，便于扩展和备份。

### 7.2 备份策略

```bash
# 定期备份 uploads 目录和数据库
# 示例：每日凌晨 2 点备份
0 2 * * * tar -czf /backups/uploads-$(date +\%Y\%m\%d).tar.gz /data/nynu-code-lab/uploads/
0 2 * * * mysqldump -h localhost -u nynu -p<password> nynu_code_lab | gzip > /backups/db-$(date +\%Y\%m\%d).sql.gz
```

### 7.3 对象存储替代方案

如文件量较大（> 10GB），建议将文件存储迁移到对象存储服务（如阿里云 OSS、腾讯云 COS、AWS S3），通过 CDN 加速访问：

- 修改 `UploadFileServiceImpl`，将文件上传到对象存储而非本地文件系统
- `accessUrl` 返回 CDN URL
- 不再需要 Nginx 静态文件服务和 volume 挂载

### 7.4 安全建议

- 上传接口限流：防止恶意上传耗尽磁盘，可在 Nginx 或后端增加速率限制
- 文件类型白名单：严格限制为图片类型，禁止 SVG（可包含脚本）
- 对上传图片进行重编码/压缩，去除可能的恶意元数据（使用 ImageMagick 或类似工具）
- 定期清理未使用的上传文件（`lab_upload_file` 表有记录但其他表未引用的文件）
- uploads 目录不要放在 web 根目录下，必须通过 Nginx `alias` 精确路径暴露
