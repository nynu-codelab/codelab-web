# 生产环境配置说明

> 日期：2026-06-22

## 1. 环境变量总览

所有环境变量定义在 `deploy/.env`（从 `deploy/.env.example` 复制并填写）。Docker Compose 通过 `--env-file .env` 注入到容器中。

| 环境变量 | 默认值 | 说明 |
|----------|--------|------|
| `SPRING_PROFILES_ACTIVE` | `docker` | Spring 激活的 profile，生产必须为 `docker` |
| `SERVER_PORT` | `8080` | 后端应用端口 |
| `BACKEND_PORT` | `8080` | 对外暴露的后端端口（通常与 SERVER_PORT 一致） |
| `MYSQL_ROOT_PASSWORD` | （必填） | MySQL root 密码 |
| `MYSQL_DATABASE` | `nynu_code_lab` | 数据库名 |
| `MYSQL_USER` | `nynu` | 应用连接数据库的用户名 |
| `MYSQL_PASSWORD` | （必填） | 应用连接数据库的密码 |
| `MYSQL_PORT` | `3306` | MySQL 端口 |
| `REDIS_PORT` | `6379` | Redis 端口（预留，当前未使用） |
| `REDIS_PASSWORD` | （可选） | Redis 密码 |
| `JWT_SECRET` | （必填） | JWT 签名密钥 |
| `NGINX_PORT` | `80` | Nginx 对外端口 |
| `UPLOAD_BASE_PATH` | `uploads` | 文件上传存储路径 |

## 2. 数据库配置

### 2.1 环境变量说明

数据库连接配置在 `backend/src/main/resources/application-docker.yml` 中，通过环境变量注入：

```yaml
spring:
  datasource:
    url: jdbc:mysql://${MYSQL_HOST:mysql}:${MYSQL_PORT:3306}/${MYSQL_DATABASE:nynu_code_lab}?useUnicode=true&characterEncoding=utf-8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
    username: ${MYSQL_USER:nynu}
    password: ${MYSQL_PASSWORD:change_me}
```

### 2.2 生产环境设置步骤

1. 复制模板文件：

```bash
cd deploy
cp .env.example .env
```

2. 编辑 `.env`，设置强密码：

```bash
MYSQL_ROOT_PASSWORD=<生成强密码，至少16位>
MYSQL_PASSWORD=<生成强密码，至少16位>
```

3. `MYSQL_HOST` 在 Docker Compose 环境中无需额外设置（默认使用 Docker 服务名 `mysql`）。如使用外部数据库，在 `docker-compose.yml` 中为 backend 服务添加：

```yaml
environment:
  - MYSQL_HOST=your-external-db-host
```

### 2.3 数据库初始化

首次部署时，MySQL 容器会自动执行 `deploy/mysql/init/01-init.sql` 创建 10 张表并插入种子数据。该脚本为幂等设计（`DROP TABLE IF EXISTS` + `CREATE TABLE`），重复执行即可重建。

注意：已有生产数据的数据库**不得**直接执行 DROP+CREATE 初始化脚本，需单独编写增量迁移 SQL。

## 3. JWT 密钥

### 3.1 生成强密钥

```bash
openssl rand -base64 64
```

将输出粘贴到 `.env` 的 `JWT_SECRET` 字段：

```bash
JWT_SECRET=<上面生成的密钥>
```

### 3.2 密钥要求

- 长度至少 32 字符
- 包含大小写字母、数字、特殊字符
- 每个环境使用不同的密钥
- 密钥泄露后立即更换（更换后所有已签发 token 失效）

### 3.3 Token 配置

`application.yml` 中 `sa-token` 相关配置：

| 配置项 | 值 | 说明 |
|--------|-----|------|
| `sa-token.token-name` | `Authorization` | Token 在请求头中的名称 |
| `sa-token.timeout` | `604800` | Token 有效期（秒），默认 7 天 |
| `sa-token.token-style` | `tik` | Token 风格 |
| `sa-token.token-prefix` | `Bearer` | 前端请求头前缀 |
| `sa-token.jwt-secret-key` | `${JWT_SECRET:...}` | JWT 签名密钥，从环境变量注入 |

## 4. 文件上传配置

### 4.1 后端配置

`application.yml`：

```yaml
app:
  upload:
    base-path: ${UPLOAD_BASE_PATH:uploads}
    url-prefix: /uploads
spring:
  servlet:
    multipart:
      enabled: true
      max-file-size: 10MB
      max-request-size: 10MB
```

### 4.2 生产环境设置

1. 在 `.env` 中设置上传目录：

```bash
UPLOAD_BASE_PATH=/app/uploads
```

2. 在 `docker-compose.yml` 中确保 uploads 目录通过 volume 挂载到宿主机：

```yaml
services:
  backend:
    volumes:
      - uploads_data:/app/uploads

volumes:
  uploads_data:
```

### 4.3 Nginx 静态文件映射

Nginx 需配置 `/uploads/` 路径映射到 uploads 目录，使上传的文件可通过 URL 访问：

```nginx
location /uploads/ {
    alias /usr/share/nginx/html/uploads/;
    expires 30d;
    add_header Cache-Control "public, immutable";
}
```

Docker Compose 中 Nginx 需要挂载同一个 uploads volume：

```yaml
services:
  nginx:
    volumes:
      - uploads_data:/usr/share/nginx/html/uploads:ro
```

### 4.4 支持的文件类型

- 图片：jpg、jpeg、png、webp
- 单文件最大 10MB
- 禁止上传可执行文件（exe、sh、bat 等）

### 4.5 文件命名规则

上传文件以 `UUID + 原始扩展名` 重命名存储，例如：

```
uploads/2026/06/a1b2c3d4-e5f6-7890-abcd-ef1234567890.jpg
```

数据库 `lab_upload_file` 表记录包含原始文件名、存储文件名、MIME 类型、文件大小、访问 URL 等元信息。

## 5. 前端 API 地址

### 5.1 前台 web

前台 Vite 构建时通过环境变量 `VITE_API_BASE_URL` 指定后端 API 地址。

`.env.production`（或构建时传入）：

```bash
VITE_API_BASE_URL=/api
```

Nginx 统一托管时，前台与后端同域，API 路径使用相对路径 `/api` 即可。

如前后端分离部署，需设置为完整 URL：

```bash
VITE_API_BASE_URL=https://api.example.com/api
```

### 5.2 后台 admin-web

同样通过 `VITE_API_BASE_URL` 配置：

```bash
VITE_API_BASE_URL=/api
```

### 5.3 构建命令

```bash
# 前台
cd web
VITE_API_BASE_URL=/api npm run build

# 后台
cd admin-web
VITE_API_BASE_URL=/api npm run build
```

## 6. Nginx 配置

### 6.1 完整配置示例

```nginx
server {
    listen 80;
    server_name your-domain.com;

    # 前台 SPA
    location / {
        root /usr/share/nginx/html/web;
        index index.html;
        try_files $uri $uri/ /index.html;
    }

    # 后台 SPA（/admin/ 路径）
    location /admin/ {
        alias /usr/share/nginx/html/admin-web/;
        try_files $uri $uri/ /admin/index.html;
    }

    # 后端 API 反向代理
    location /api/ {
        proxy_pass http://backend:8080/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # 文件上传大小限制
        client_max_body_size 10m;
    }

    # 上传文件静态服务
    location /uploads/ {
        alias /usr/share/nginx/html/uploads/;
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    # API 文档
    location /doc.html {
        proxy_pass http://backend:8080/doc.html;
    }

    location /v3/ {
        proxy_pass http://backend:8080/v3/;
    }
}
```

### 6.2 HTTPS 配置（生产环境）

生产环境必须启用 HTTPS。建议使用 Let's Encrypt 免费证书或云服务商提供的 SSL 证书。

```nginx
server {
    listen 443 ssl http2;
    server_name your-domain.com;

    ssl_certificate /etc/nginx/ssl/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;

    # ... 其余配置同上 ...
}

# HTTP → HTTPS 跳转
server {
    listen 80;
    server_name your-domain.com;
    return 301 https://$server_name$request_uri;
}
```

### 6.3 Docker Compose 中的 Nginx 配置

项目 Nginx 配置文件位于 `deploy/nginx/nginx.conf`。修改后重建 Nginx 容器：

```bash
cd deploy
docker compose --env-file .env up -d --build nginx
```

## 7. 管理员账号

### 7.1 默认账号

数据库初始化脚本 `deploy/mysql/init/01-init.sql` 中预置管理员账号：

| 字段 | 值 |
|------|-----|
| 用户名 | `admin` |
| 密码 | `admin123`（BCrypt 加密存储） |
| 角色 | `ADMIN` |

### 7.2 首次登录后必须修改密码

管理员首次登录后，必须立即通过个人中心或后台修改密码入口更改默认密码。路径：

- **前台**：登录后进入个人中心（`/profile`），点击"修改密码"
- **后台**：登录后点击右上角用户下拉菜单，选择"修改密码"

### 7.3 密码强度要求

- 至少 6 个字符
- 建议：8 位以上，包含大小写字母、数字、特殊字符

## 8. 安全提醒

### 8.1 部署前必须修改

- `MYSQL_ROOT_PASSWORD` — 改为强随机密码
- `MYSQL_PASSWORD` — 改为强随机密码
- `JWT_SECRET` — 改为 `openssl rand -base64 64` 生成的强密钥
- 管理员默认密码 `admin123` — 首次登录后修改

### 8.2 敏感信息保护

- `deploy/.env` 已加入 `.gitignore`，不会被提交到 Git
- 绝对不要在 `application.yml`、`application-docker.yml` 或任何 Java/Vue 源码中硬编码真实密码、密钥
- Docker Compose 配置中敏感值使用 `${VAR}` 形式引用环境变量，不写死
- `deploy/.env.example` 作为模板可以提交，所有敏感值留空

### 8.3 检查清单

```bash
# 确认 .env 未被提交
git status --short | grep -F .env && echo "WARNING: .env may be tracked" || echo "OK"

# 确认没有硬编码密码
grep -r "password.*=.*change_me" backend/src/ --include="*.yml" && echo "WARNING: default password in yml" || echo "OK"
grep -r "nynu_code_lab_jwt_secret_key" backend/src/ --include="*.yml" && echo "WARNING: default JWT secret in yml" || echo "OK"

# 确认 .env 中敏感变量已填写（非空）
grep -E '^MYSQL_ROOT_PASSWORD=$|^MYSQL_PASSWORD=$|^JWT_SECRET=$' deploy/.env && echo "WARNING: some required vars are empty" || echo "OK"
```

### 8.4 其他安全建议

- 生产环境务必启用 HTTPS，禁止 HTTP 明文传输
- 配置防火墙，仅开放 80/443 端口，不暴露 3306（MySQL）、6379（Redis）、8080（Backend）到公网
- 定期备份数据库和 uploads 目录
- Token 黑名单和登录限流当前为内存实现（服务重启丢失），生产环境建议切换为 Redis
- 关注后台 `npm audit` 报告的依赖漏洞，定期升级
