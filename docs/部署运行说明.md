## 3. 本地开发启动

### 3.1 前置条件

本机需安装 Java 17、Maven 3.9+、Node.js 20+、MySQL 8。

### 3.2 初始化数据库

```bash
mysql -u root -p < deploy/mysql/init/01-init.sql
```

### 3.3 启动后端

```bash
cd backend
mvn spring-boot:run
# 默认 local profile，连接 localhost:3306
```

### 3.4 启动前端

```bash
# 前台（端口 5173）
cd web
npm install
npm run dev

# 后台（端口 5174）
cd admin-web
npm install
npm run dev
```

### 3.5 访问地址

| 入口 | 地址 |
|------|------|
| 前台 | http://localhost:5173 |
| 后台 | http://localhost:5174/admin/ |
| API 文档 | http://localhost:8080/doc.html |

## 4. Docker Compose 启动

### 4.1 前置条件

Docker Desktop / Docker Engine + Docker Compose v2。

### 4.2 一键启动

```bash
cd deploy

# 1. 创建环境变量文件
cp .env.example .env
# 编辑 .env 修改密码和密钥（尤其是 JWT_SECRET）

docker compose --env-file .env up -d --build

# 3. 查看运行状态
docker compose ps

# 4. 查看日志
docker compose logs -f backend
```

复制 `deploy/.env.example` 为 `deploy/.env`，修改以下变量：

### 5.2 一键生成密码

```bash
echo "MYSQL_ROOT_PASSWORD=$(openssl rand -base64 24)"
echo "MYSQL_PASSWORD=$(openssl rand -base64 20)"
echo "REDIS_PASSWORD=$(openssl rand -base64 20)"
echo "JWT_SECRET=$(openssl rand -base64 64)"
```

### 5.3 Profile 说明

| Profile | 数据库连接 | Redis 认证 | 使用场景 |
|---|---|---|---|
| `local`（默认） | `localhost:3306` | 内存实现 | 本地开发，本机 MySQL |
| `docker` | `mysql:3306`（容器服务名） | Redis 实现 | Docker Compose 部署 |

> Docker profile 中禁止写 `localhost` 作为中间件地址，必须使用 Docker Compose service name。

## 6. 数据库初始化

Docker Compose 首次启动时自动执行 `deploy/mysql/init/01-init.sql`：

- 创建 `nynu_code_lab` 数据库（utf8mb4）
- 创建 10 张表（sys_user、lab_apply_record、lab_article、lab_article_category、lab_article_tag、lab_project、lab_member、lab_direction、lab_site_config、lab_upload_file）
- 插入种子数据：默认管理员 `admin`/`admin123`、5 个技术方向、4 个文章分类、6 个标签、11 项站点配置

> ⚠️ `admin`/`admin123` 仅用于本地开发演示。生产环境必须修改默认密码。
> 已有生产数据的数据库不得直接执行 DROP+CREATE 初始化脚本，需单独编写增量迁移。

### 手动初始化（本地开发）


## 7. 文件上传配置

### 7.1 安全策略：7 层纵深防御

| 层 | 防御内容 | 说明 |
|---|---|---|
| 1 | 文件非空检查 | 拒绝 null 和空文件 |
| 2 | 文件名安全清洗 | 拒绝 `../`、`..\\`、空字节截断 |
| 3 | 扩展名白名单 | 仅允许 `.jpg`、`.jpeg`、`.png`、`.webp` |
| 4 | MIME 类型校验 | `image/jpeg`、`image/png`、`image/webp` |
| 5 | Magic Bytes 校验 | 读取文件头字节比对，不可伪造的最终防线 |
| 6 | 文件大小上限 | 10MB |
| 7 | 安全存储 | UUID 重命名 + `yyyy/MM/dd` 日期子目录 |

### 7.2 存储路径

```
{base-path}/
└── 2026/
    └── 06/
        └── 22/
            └── a1b2c3d4-e5f6-7890-abcd-ef1234567890.jpg
```

- 本地开发：`backend/uploads/`
- Docker 部署：`/app/uploads`（通过 volume 挂载到宿主机）

### 7.3 Docker Volume 配置

```yaml
services:
  backend:
    volumes:
      - uploads_data:/app/uploads
    environment:
      - UPLOAD_BASE_PATH=/app/uploads
  nginx:
    volumes:
      - uploads_data:/usr/share/nginx/html/uploads:ro  # 只读挂载
```

### 7.4 Nginx 静态文件配置

```nginx
location /uploads/ {
    alias /usr/share/nginx/html/uploads/;
    expires 30d;
    add_header Cache-Control "public, immutable";
}
```

### 7.5 上传接口

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/admin/upload` | 上传文件（multipart/form-data, 参数 `file` + `usageType`） |
| GET | `/api/admin/upload` | 获取最近上传文件列表（最近 50 条） |
| DELETE | `/api/admin/upload/{id}` | 删除文件记录及物理文件 |

## 9. 数据备份与恢复

### 9.1 备份体系

| 备份对象 | 备份方式 | 周期建议 | 保留策略 |
|----------|---------|----------|----------|
| MySQL 数据库 | `mysqldump` SQL 导出 | 每日 | 至少 7 天 |
| 上传文件目录 | `tar -czf` 归档压缩 | 每日 | 至少 7 天 |
| Redis 数据 | AOF 持久化（自动） | 实时 | 非核心业务主数据 |

### 9.2 MySQL 备份

```bash
# 从 deploy/.env 读取配置
source deploy/.env

docker compose --env-file deploy/.env -f deploy/docker-compose.yml exec -T mysql \
  mysqldump \
    -u"$MYSQL_USER" \
    -p"$MYSQL_PASSWORD" \
    --single-transaction \
    --routines \
    --triggers \
    "$MYSQL_DATABASE" \
  > /opt/codelab/backup/mysql/codelab_$(date +%Y%m%d_%H%M%S).sql

gzip /opt/codelab/backup/mysql/codelab_*.sql
```

### 9.3 MySQL 恢复

```bash
source deploy/.env
BACKUP_FILE="/opt/codelab/backup/mysql/codelab_20260622_030000.sql"

# 恢复前建议停止后端写入
docker compose stop backend

docker compose --env-file deploy/.env -f deploy/docker-compose.yml exec -T mysql \
  mysql -u"$MYSQL_USER" -p"$MYSQL_PASSWORD" "$MYSQL_DATABASE" < "$BACKUP_FILE"

docker compose start backend
```

### 9.4 上传文件备份

```bash
docker run --rm \
  -v nynu-code-lab_uploads-data:/data:ro \
  -v /opt/codelab/backup/uploads:/backup \
  alpine \
  tar -czf /backup/uploads_$(date +%Y%m%d_%H%M%S).tar.gz -C /data .
```

### 9.5 上传文件恢复

```bash
BACKUP_FILE="/opt/codelab/backup/uploads/uploads_20260622_030000.tar.gz"

docker run --rm \
  -v nynu-code-lab_uploads-data:/data \
  -v /opt/codelab/backup/uploads:/backup:ro \

  tar -xzf "/backup/$(basename "$BACKUP_FILE")" -C /data
```

```bash
  -v /opt/codelab/backup/uploads:/backup alpine \
```


### 11.4 HTTPS 配置

生产环境必须启用 HTTPS。推荐使用 Let's Encrypt 免费证书。

**申请证书：**

```bash
docker run -it --rm -v /opt/codelab/ssl:/etc/letsencrypt \
  certbot/certbot certonly --standalone \
  -d your-domain.com
```

**Docker Compose 挂载证书：**

```yaml
nginx:
  volumes:
    - /opt/codelab/ssl:/etc/nginx/ssl:ro
```

**Nginx HTTPS 配置模板：**

```nginx
# HTTP → HTTPS 跳转
server {
    listen 80;
    server_name your-domain.com;
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    server_name your-domain.com;

    ssl_certificate /etc/nginx/ssl/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;

    client_max_body_size 10M;

    # API 代理
    location /api/ {
        proxy_pass http://backend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # 上传文件静态服务
    location /uploads/ {
        alias /usr/share/nginx/html/uploads/;
        expires 30d;
    }

    # API 文档
    location /doc.html { proxy_pass http://backend; }
    location /v3/      { proxy_pass http://backend; }
    location /swagger-ui/ { proxy_pass http://backend; }

    # 后台 SPA
    location /admin/ {
        alias /usr/share/nginx/html/admin/;
        try_files $uri $uri/ /admin/index.html;
    }

    # 前台 SPA
    location / {
        root /usr/share/nginx/html;
        try_files $uri $uri/ /index.html;
    }
}
```

## 12. Redis 认证服务

### 12.1 架构

Docker 环境使用 Redis 实现 Token 黑名单和登录限流，支持多实例部署。

| Profile | 实现 |
|---|---|
| `local` | 内存实现（`InMemoryTokenBlacklistService` + `InMemoryLoginAttemptService`） |
| `docker` | Redis 实现（`RedisTokenBlacklistService` + `RedisLoginAttemptService`） |

### 12.2 Redis Key 设计

| 用途 | Key 格式 | TTL |
|---|---|---|
| Token 黑名单 | `codelab:auth:blacklist:{sha256(token)}` | token 剩余有效期 |
| 登录尝试计数 | `codelab:auth:login-attempt:{ip}:{username}` | 10 分钟 |
| 登录锁定标记 | `codelab:auth:login-lock:{ip}:{username}` | 10 分钟 |

> 安全设计：不存储完整 Token，仅保存 SHA-256 摘要。

### 12.3 数据丢失影响

Redis 中的数据均有 TTL 自动过期，丢失后的影响是安全降级（已登出 Token 在有效期内可重新使用），非数据丢失。业务主数据均在 MySQL 中。

### Q: 首次部署后数据库表不全？

如果 MySQL 数据卷已有历史数据，init SQL 不会重新执行。解决：

```bash
# 方式一：重建数据卷（会清空数据）
docker compose down -v && docker compose --env-file .env up -d --build

# 方式二：手动执行初始化脚本
docker compose exec -T mysql mysql -u root -p < deploy/mysql/init/01-init.sql
```

## 15. 不提交 Git 的文件

| 文件 | 原因 |
|------|------|
| `deploy/.env` | 含数据库密码、JWT 密钥 |
| `.env` | 可能含敏感信息 |
| `*.pem`、`*.key`、`*.crt` | HTTPS 证书和私钥 |
| `*.sql.gz`、备份 `*.sql` | 数据库备份含用户数据 |
| `data/`、`backup/` 目录 | 持久化数据和备份 |

验证命令：

```bash
git ls-files .env deploy/.env        # 预期空输出
git check-ignore -v .env deploy/.env # 预期显示 .gitignore 行号
```
