# 南阳师范学院 Code Lab 实验室 — 项目说明

> 本网站为南阳师范学院 Code Lab 实验室自建展示站，非学校官方门户网站。

## 1. 项目基本信息

| 项 | 值 |
|---|---|
| 中文名称 | 南阳师范学院 Code Lab 实验室网站与招新管理系统 |
| 英文名称 | Nanyang Normal University Code Lab |
| Git 仓库名 | `nynu-code-lab` |
| 项目定位 | 实验室自建技术展示与招新管理平台 |

## 2. 项目目标

1. 建设实验室对外展示窗口，提升实验室形象
2. 展示实验室技术方向、核心成员、项目成果和学习文章
3. 沉淀实验室内部技术分享、项目复盘等内容
4. 支持学生在线注册、登录和提交招新报名
5. 支持管理员在后台维护官网内容和审核报名信息
6. 为实验室后续长期运营和内容沉淀打基础

## 3. 目标用户

| 用户类型 | 说明 |
|---|---|
| 南阳师范学院在校学生 | 了解实验室、浏览内容、报名加入 |
| 实验室管理员 | 维护官网内容、审核报名、管理后台 |
| 校外访客 | 了解实验室技术方向和成果 |

## 4. 系统角色

第一版系统角色分为三类：

| 角色 | 标识 | 权限概述 |
|---|---|---|
| 游客 | VISITOR | 浏览公开页面（首页、介绍、方向、成员、项目、文章、招新介绍、联系我们），不可报名 |
| 普通用户 | USER | 注册登录、提交招新报名、查看自己的报名状态、修改密码、浏览文章和项目 |
| 管理员 | ADMIN | 管理用户、审核报名、管理文章、管理项目、管理成员、管理技术方向、管理站点配置、上传图片、查看数据概览 |

第一版不做复杂 RBAC 权限系统。

## 6. 核心业务流程

### 6.1 招新报名闭环

```
注册账号 → 登录系统 → 填写报名信息 → 提交报名 → 管理员审核 → 用户查看审核状态
```

报名状态流转（8 种）：

```
PENDING → VIEWED → CONTACTED → PRELIMINARY_PASSED → INTERVIEWING → PASSED
                                                                    ↘ REJECTED
用户可在 PENDING/VIEWED 状态撤回 → WITHDRAWN
```

约束：
- 必须登录后才能提交报名
- 一个用户只能有一条有效报名记录（已撤回的不计入）
- 普通用户只能查看和修改自己的报名
- 审核结果仅在系统内展示（无短信/邮件/QQ 通知）

### 6.2 文章发布流程

```
管理员创建草稿 → 编辑 Markdown 内容 → 发布 → 前台可见
                                        → 下架 → 前台不可见
                                        → 删除（软删除）
```

Markdown 渲染使用 `markdown-it`，配置 `html: false` 防止 XSS。

### 6.3 项目展示流程

```
管理员创建草稿 → 编辑内容 → 发布 → 前台列表/详情可见
                            → 设置精选 → 首页精选区展示
                            → 下架 → 前台不可见
```

## 7. 报名表字段

| 字段 | 是否必填 | 说明 |
|------|----------|------|
| 姓名 | 是 | 报名人真实姓名 |
| 年级 | 是 | 例如 2024 级 |
| 专业 | 是 | 学生专业 |
| 班级 | 是 | 学生所在班级 |
| 手机号 | 是 | 联系方式，第一版不做短信验证码 |
| QQ号 | 建议必填 | 后续联系使用 |
| 意向技术方向 | 是 | Java 后端、前端开发、微信小程序等 |
| 是否有编程基础 | 是 | 便于初筛 |
| 已掌握技术 | 否 | 例如 Java、HTML、CSS、Vue、MySQL |
| 个人介绍 | 是 | 简要介绍个人情况 |
| 加入实验室的原因 | 建议必填 | 判断动机 |
| 每周可投入时间 | 建议必填 | 判断时间投入 |
| 项目/作品链接 | 否 | GitHub、Gitee、博客或作品地址 |

## 10. 已实现能力总览

### ✅ 已完整实现

- 用户注册/登录/登出/修改密码（BCrypt 加密，Sa-Token JWT）

- 招新报名闭环（8 种状态流转 + 招新开关）
- 文章管理（Markdown 编辑/渲染，`html:false` 防 XSS，分页+关键词搜索）
- 项目成果管理（发布/下架/精选，分页+状态筛选）
- 成员管理（完整 CRUD + 状态筛选）
- 技术方向管理（完整 CRUD + 启用/禁用）
- 站点配置管理（key-value CRUD，含联系方式、招新开关等 11 项）
- 文件上传（7 层纵深防御：Magic Bytes + 路径穿越防护 + UUID 重命名 + 日期子目录 + 10MB 限制）
- 数据概览（9 项真实统计指标）
- 用户管理（分页/搜索/禁用/角色修改/密码重置）

## 11. 安全与质量要求

| 类别 | 要求 |
|---|---|
| 密码 | BCrypt 加密，禁止明文/MD5 |
| Token | JWT 模式，7 天有效期 |
| 登录 | IP+用户名限流，5 次失败锁定 10 分钟 |
| 用户状态 | 支持禁用，禁用后不可登录 |
| 权限 | 游客→公开接口，普通用户→自己数据，管理员→全部后台 |
| 文件上传 | 7 层纵深防御（Magic Bytes + 路径穿越 + 扩展名白名单 + UUID 重命名） |
| Markdown | `html:false`，不渲染原始 HTML |
| 敏感信息 | 禁止提交数据库密码、Token 密钥、服务器私钥到 Git |
| 前端 | 接口统一封装、Token 统一处理、错误统一提示 |
